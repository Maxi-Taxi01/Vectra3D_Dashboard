# Vectra3D graduation workspace

Open `Dashboard/index.html` in your usual browser, or double-click `Open dashboard.cmd`. No installation or account needed. The dashboard is private to this computer unless you share the files.

## First use
For the broader goal of graduation, business profit and future skills, start with `00_Project_control/Goal_scorecard.md`. Use `09_Business/Capacity_and_profit_review.md` at the next sponsor conversation and `Templates/Learning_evidence_log.md` to capture student-authored learning through existing work.

1. Review This week and the open approval/calendar tasks. All task progress starts as Not started because actual completion is unknown; enter work already completed.
2. Use Tasks to change status. Use Deliverables to record an administrative evidence file reference and review status. Do not paste research findings.
3. Update aggregate recruitment counts in Research planning. Zero means no count entered yet. No participant identities or raw session material.
4. Log hours under Graduation or Business; the weekly targets are separate. Record supervision dates and administrative actions.
5. Every Friday, complete the weekly review and choose Export backup. Save the JSON into Backups on this computer or another approved access-controlled location (not portable media containing personal data).

## Saving and recovery
Changes save in this browser's local storage, not into the HTML files. Use the same browser and dashboard address. Clearing browser data, private browsing or moving the dashboard can lose/separate saved state. Export JSON regularly. Restore validates a matching dashboard backup and asks before replacing current entries. Keep older backups; restore is a replacement, not a merge. Export the calendar only after reviewing provisional dates; it does not create reminders or appointments automatically.

When another tab changes or clears the saved dashboard, automatic saving pauses and a persistent warning appears. Choose **Export these edits** before reloading. This preserves the current tab's work as a download; it does not merge conflicting versions. Failed saves also remain visibly flagged.

Before restoring a backup, the dashboard preserves the previous valid saved version in this browser. **Export pre-restore copy** in Weekly review or Files & guidance downloads that version for recovery through Restore backup. Only the most recent pre-restore version is retained. This browser copy is not a substitute for external JSON backups and is lost if browser storage is cleared.

## Schedule and evidence updates
Edit linked deadlines in Tasks. The current milestone table, Coming up list and **Export current calendar** use those edited dates while keeping original source dates visible. Edited dates are marked for confirmation; changes do not amend the approved proposal. Review-week markers and the agreement end date retain their source dates. Reimporting an exported calendar may create duplicates depending on your calendar app; review existing events first.

Evidence references save as you type. Deliverables reports how many outputs are marked Ready without an evidence reference. Weekly review also counts blocked tasks and past-date tasks to verify. These checks support review; they do not judge the quality of research or grant approval.

## Work rhythm
Daily: select priorities, do student-owned research/design, record hours and evidence locations.
Weekly: check gates, participant access, deliverables, risks, 40 graduation hours and max 4 commercial hours; back up.
Every two weeks: 30-minute sponsor meeting; prepare evidence and decisions. Confirm actual dates.
At phase reviews: export status; obtain required approvals before fundamental plan changes.
Before publication/submission: use the templates, confirm permissions, and archive approved final versions.
